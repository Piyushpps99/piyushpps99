UNIT I — Introduction to Information Systems & Security

1.1 Introduction to Information Systems

An Information System (IS) is a combination of people, hardware, software, data, and processes that work together to collect, process, store and distribute information. Its main purpose is to help people make better decisions and run the organization smoothly.

Simple Meaning
An information system takes raw data as input, processes it, and gives useful information as output that managers and employees can use.

Main components: Hardware · Software · Data · People · Processes / Procedures · Networks

Example
A college admission system takes student applications (data), checks eligibility (process), stores records (database), and shows the list of selected students (information) to the administration.

1.2 Types of Information Systems

  1. Transaction Processing System (TPS) — Records day-to-day transactions (billing, payroll, ATM). Foundation for other systems.
  2. Management Information System (MIS) — Summary reports for middle managers (monthly sales, inventory status).
  3. Decision Support System (DSS) — Helps non-routine decisions by analyzing data and showing outcomes.
  4. Executive Information System (EIS/ESS) — High-level dashboards for top executives.
  5. Expert System — Copies decision-making of a human expert (medical diagnosis, loan approval).
  6. Office Automation System (OAS) — Email, word processing, spreadsheets, video conferencing.
  7. Knowledge Management System (KMS) — Stores and shares employee knowledge (company wiki, best-practice database).

1.3 Development of Information Systems (SDLC)

  1. Planning / Feasibility Study
  2. System Analysis
  3. System Design
  4. Implementation / Coding
  5. Testing
  6. Deployment
  7. Maintenance

Modern approaches: Agile, Prototyping, DevOps.

1.4 Information Security & the CIA Triad

Information Security means protecting information and systems from unauthorized access, use, disclosure, disruption, modification, or destruction.

1. Confidentiality

Only authorized people can see the information. Secret data must remain secret.

Methods: encryption, passwords, access control

2. Integrity

Information must be accurate and complete. No unauthorized changes.

Methods: checksums, digital signatures, version control

3. Availability

Systems and information available to authorized users when needed.

Methods: backups, redundant servers, anti-DoS measures

Remember
If any one of CIA is broken, security is compromised. Good security balances all three.

1.5 Need for Information Security

  • Huge amounts of sensitive data stored by organizations
  • Almost everything is connected to the internet — large attack surface
  • Cyber attacks cause financial loss, legal problems, and reputation damage
  • Laws and regulations require protection of data
  • Business continuity depends on available and correct systems
  • Customer and partner trust depends on security
  • National security and critical infrastructure depend on secure systems

1.6 Threats to Information Systems

  • Human threats — hackers, disgruntled employees, social engineers, careless users
  • Malicious software — viruses, worms, ransomware, spyware, trojans
  • Network attacks — DoS, man-in-the-middle, packet sniffing
  • Physical threats — theft, fire, flood, power failure, vandalism
  • Technical failures — hardware crash, software bugs, configuration errors
  • Natural disasters — earthquake, flood, cyclone
  • Organizational threats — weak policies, lack of training, poor access control

1.7 Information Assurance & Security Risk Analysis

Information Assurance means confidence that systems will work as expected and that CIA is protected.

Simple steps of Risk Analysis:

  1. Identify assets
  2. Identify threats and vulnerabilities
  3. Assess likelihood and impact
  4. Calculate risk (Risk ≈ Likelihood × Impact)
  5. Decide treatment — Accept, Avoid, Transfer, or Mitigate
  6. Implement controls and monitor

1.8 Cyber Security — Overview

Cyber Security is the practice of protecting computers, networks, programs and data from digital attacks. It covers network security, application security, endpoint security, cloud security, identity & access management, and security awareness training.

Key Message
In today’s world, cyber security is not optional. Every organization — big or small — needs a basic level of cyber security to survive and retain customer trust.
UNIT II — Application Security, Data Security & Threats

2.1 Application Security — Database, Email & Internet

Database Security

  • Strong authentication and authorization
  • Encryption of sensitive data (at rest and in transit)
  • Regular backups and tested recovery
  • Input validation to prevent SQL Injection
  • Activity monitoring and auditing
  • Principle of least privilege

Email Security

  • Anti-spam and anti-malware filters
  • SPF, DKIM, DMARC to prevent spoofing
  • User awareness training
  • Encryption of sensitive emails
  • Multi-factor authentication

Web Application Security

Secure coding, regular patching, HTTPS everywhere, Web Application Firewall (WAF), input validation, vulnerability scanning and penetration testing.

2.2 Data Security Considerations

  • Backups — 3-2-1 rule: 3 copies, 2 media types, 1 off-site. Test restores regularly.
  • Archival Storage — Long-term storage for legal/compliance reasons; still protect with encryption and access control.
  • Disposal of Data — Secure wipe, degaussing, physical destruction. Simple delete is not enough.

2.3 Security Technology — Firewall, VPN, IDS

  • Firewall — Controls traffic between trusted and untrusted networks based on rules. Types: packet-filtering, stateful, proxy, NGFW.
  • VPN — Creates encrypted tunnel over public network. Protocols: IPsec, OpenVPN, WireGuard, SSL VPN.
  • IDS — Monitors for suspicious activity and raises alerts (NIDS / HIDS). IPS can also block attacks automatically.

2.4 Access Control

Steps: Identification → Authentication → Authorization → Accounting / Auditing

Models:

  • DAC — Owner decides access
  • MAC — System policy based on security labels (military)
  • RBAC — Permissions given to roles; users assigned roles
Best Practice
Principle of Least Privilege — give users only the minimum access they need to do their job.

2.5 Security Threats — Malicious Software

  • Virus — Attaches to legitimate files; needs human action to spread
  • Worm — Spreads automatically over networks without human action
  • Trojan — Pretends to be useful; performs hidden harmful actions; does not self-replicate
  • Logic Bomb — Triggers on a condition (date or event)
  • Backdoor / Trapdoor — Hidden access that bypasses authentication
  • Spoofing — Pretending to be someone/something else
  • Ransomware — Encrypts files and demands payment
  • Spyware / Adware / Rootkit / Keylogger

2.6 Network Attacks & Denial of Service

DoS overwhelms a system so legitimate users cannot access it. DDoS uses many computers (botnet) at once.

Other attacks: Man-in-the-Middle, Packet Sniffing, Session Hijacking, Port Scanning.

Protection
Firewalls, IDS/IPS, rate limiting, DDoS protection services, patching, and network segmentation help reduce impact.
UNIT III — E-Commerce Security & Secure Systems

3.1 E-Commerce and its Threats

E-Commerce is buying and selling using the internet. Threats include theft of customer data, phishing, payment fraud, DoS during sales, man-in-the-middle, insider threats, and malware on payment pages (e.g., Magecart).

3.2 Electronic Payment Systems

  • Credit / Debit Cards (OTP, 3D Secure, CVV, tokenization)
  • e-Cash / Digital Wallets / UPI
  • Net Banking
  • Prepaid / Gift Cards

Security requirements: encryption (HTTPS/TLS), strong authentication, PCI-DSS compliance, fraud detection.

3.3 Digital Signature and Cryptography

Cryptography protects information by transforming it. Goals: confidentiality, integrity, authentication, non-repudiation.

  • Symmetric Encryption — Same key for encrypt/decrypt (AES). Fast; key sharing is a challenge.
  • Asymmetric Encryption — Public + private key pair (RSA). Solves key distribution.
  • Hashing — One-way fingerprint (SHA-256) for integrity checks.

Digital Signature — Created with private key, verified with public key. Provides authentication, integrity, and non-repudiation. Legally recognized in India under IT Act 2000.

3.4 Developing Secure Information Systems

Security by Design — build security from the beginning. Practices: threat modeling, secure coding, code reviews, least privilege, defense in depth, input validation, patch management, security testing before release.

3.5 Security Governance & Risk Management

Governance is the framework of leadership, policies and controls that ensure security supports business goals. Risk management is the ongoing process of identifying, assessing, treating and monitoring risks. Top management is responsible for governance.

3.6 Security Architecture & Design

Overall design of security controls. Principles: defense in depth, least privilege, segregation of duties, fail-secure defaults, simplicity.

3.7 Hardware, Storage & Physical Security

  • Encrypt data on laptops, USBs, phones; restrict USB ports; use MDM for BYOD
  • Physical security: locks, smart cards, biometrics, visitor logs, CCTV, fire suppression, temperature control, off-site backups, UPS/generators, security guards
UNIT IV — Security Policies

4.1 Why Security Policies are Needed

A security policy is a formal document stating rules for protecting information and systems.

  • Provide clear direction and consistency
  • Reduce risk by defining acceptable use
  • Help meet legal and regulatory requirements
  • Basis for training and awareness
  • Support disciplinary action
  • Demonstrate due diligence

Policies must be reviewed regularly, updated, published, and communicated. Employees should acknowledge that they have read them.

4.2 Types of Security Policies

  • WWW / Internet Usage Policy — Allowed/prohibited sites, personal use limits, downloading, social media, monitoring notice
  • Email Security Policy — No password sharing, careful with attachments/links, no sending confidential data to personal email, monitoring notice
  • Corporate / Organization-wide Security Policy — High-level commitment, roles and responsibilities
  • Other common: Password policy, Clean desk, Remote access, Incident response, Data classification, Acceptable Use Policy (AUP)

4.3 Sample Policies & Case Study Lessons

Sample Password Policy Points
Minimum 12 characters, mix of character types, no reuse of last 5 passwords, change periodically or use long passwords with MFA, never share, report suspected compromise immediately.
Case Study Lessons
Many incidents show: technical controls exist but policies are weak or unenforced. An employee clicks a phishing link → malware → data stolen or encrypted. Investigation finds outdated training, unenforced email policy, untested backups, unclear incident response.

Lesson: Policies must exist, be known, be enforced, and be supported by training and technology. After an incident, review and improve (continuous improvement).
UNIT V — Standards, Laws & Cyber Crimes

5.1 Information Security Standards — ISO

  • ISO/IEC 27001 — Requirements for an Information Security Management System (ISMS); organizations can be certified
  • ISO/IEC 27002 — Code of practice with detailed security controls
  • Related: ISO 27005 (risk), ISO 27017/27018 (cloud), PCI-DSS (payment cards)

5.2 IT Act 2000 — Main Provisions (India)

The primary cyber law in India (amended 2008). It gives legal recognition to electronic records and digital signatures and defines cyber offences and penalties.

  • Legal recognition of electronic records and digital signatures
  • Regulation of Certifying Authorities
  • Definition of cyber crimes and penalties
  • Data protection and privacy (Section 43A — reasonable security practices)
  • Intermediary obligations and due diligence
  • Sections on hacking, identity theft, cheating by personation, privacy violation, cyber terrorism, etc.
Note
The IT Act works together with the Indian Penal Code and other laws. For serious crimes, both are used as applicable.

5.3 Intellectual Property Rights (IPR)

IPR are legal rights given to creators of inventions, literary/artistic works, designs, symbols and names. Relevant to IT: Copyright, Patents, Trademarks, Designs, Semiconductor layout designs.

5.4 Copyright, Patent & Semiconductor Law

  • Copyright (Copyright Act 1957) — Protects original literary, artistic, musical and software works. Software treated as literary work. Duration: generally life of author + 60 years.
  • Patent (Patents Act 1970) — Protects new inventions that are novel, inventive and industrially applicable. Exclusive rights for 20 years. Software “as such” generally not patentable in India.
  • Semiconductor Law (Semiconductor Integrated Circuits Layout-Design Act 2000) — Protects layout designs of semiconductor chips.

5.5 Software Piracy and Licensing

Software Piracy is unauthorized copying, distribution or use of software. It is illegal and often brings malware risk.

Software License defines how software may be used: Proprietary, Open Source (GPL, MIT, Apache), Freeware, Shareware, Subscription/SaaS. Organizations must track licenses and avoid under-licensing.

5.6 Cyber Crimes and Cyber Laws in India

Common cyber crimes: Hacking, identity theft & phishing, online fraud, cyber stalking, publishing obscene material, data theft, ransomware, cyber terrorism, child sexual abuse material offences, electronic defamation.

Key legal provisions: IT Act 2000 (Sections 43, 43A, 65, 66, 66B–66F, 67, 67A, 67B, etc.), relevant IPC sections, Copyright Act.

Reporting Cyber Crime in India
File complaints at the local police cyber cell or through the National Cyber Crime Reporting Portal (cybercrime.gov.in). For financial frauds, report immediately to the bank and the portal to improve chances of recovery.
