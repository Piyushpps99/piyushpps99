Chapter 1: Basic Computer Structure & Von-Neumann Architecture

Key Concept: The Von-Neumann Architecture describes a stored-program computer where data and instruction code are stored in the same shared memory module and executed sequentially.

Core Components

  • Central Processing Unit (CPU):
    • Control Unit (CU): Fetches and decodes instructions; directs the flow of data inside the system.
    • Arithmetic Logic Unit (ALU): Performs all mathematical ($+$, $-$) and logical ($\text{AND}$, $\text{OR}$) operations.
  • Main Memory: Holds both program code (instructions) and data variables currently in use.
  • Input/Output (I/O) Units: Interfaces with peripherals (keyboard, monitor, storage disks).
The Von-Neumann Bottleneck: Because data and instructions share the exact same physical bus lines, the CPU is forced to alternate between fetching instructions and reading/writing data, limiting overall system speed.

Chapter 2: The Instruction Cycle & CPU Registers

Key Concept: Every computer program runs by continually looping through the Instruction Cycle.

Step-by-Step Cycle Mechanics

  1. Fetch: CPU copies the memory address from the Program Counter ($\text{PC}$) into the Memory Address Register ($\text{MAR}$). Memory reads the instruction code and moves it to the Instruction Register ($\text{IR}$). The $\text{PC}$ increments by 1.
  2. Decode: The Control Unit ($\text{CU}$) decodes the bit pattern in the $\text{IR}$ to determine the operation and identifies required operands.
  3. Execute: The CPU executes the operation via the $\text{ALU}$ or register transfer.
  4. Store / Check Interrupt: The result is stored in the Accumulator ($\text{AC}$) or memory, and any pending hardware interrupts are serviced.

Critical CPU Registers Summary

  • PC (Program Counter): Tracks the memory address of the next instruction to be executed.
  • MAR (Memory Address Register): Holds the address currently being accessed in RAM.
  • MDR/MBR (Memory Data Register): Holds the actual data payload read from or written to RAM.
  • IR (Instruction Register): Holds the instruction currently being decoded/executed.
  • AC (Accumulator): Temporary working register attached directly to the ALU output.

Chapter 4: Signed Multiplication via Booth's Algorithm

Key Concept: Booth’s Algorithm efficiently multiplies signed binary integers in 2's complement notation by replacing consecutive runs of 1s with a single addition and subtraction step.

Hardware Registers Involved

$M$: Multiplicand | $Q$: Multiplier | $A$: Accumulator (initialized to 0000) | $Q_{-1}$: Extra single-bit register (initialized to 0) | $Count$: Number of bits in operands

Action Rules Based on $(Q_0, Q_{-1})$

  • 10: Subtract Multiplicand ($A \leftarrow A - M$), then Arithmetic Shift Right (ASR) $(A, Q, Q_{-1})$.
  • 01: Add Multiplicand ($A \leftarrow A + M$), then Arithmetic Shift Right (ASR) $(A, Q, Q_{-1})$.
  • 00 or 11: Arithmetic Shift Right (ASR) $(A, Q, Q_{-1})$ only.

Worked Numerical Example: Multiply $(+7) \times (-3)$ using 4-bit numbers

$M = +7 = 0111_2$, $-M = -7 = 1001_2$ (2's complement)
$Q = -3 = 1101_2$
Initial State: $A = 0000$, $Q = 1101$, $Q_{-1} = 0$, $Count = 4$ 

1. Cycle 1: Inspect (Q_0=1, Q_-1=0) -> Action: A = A - M
   - A <- A + (-M) = 0000 + 1001 = 1001
   - ASR: A = 1100, Q = 1110, Q_-1 = 1
   - Count = 3

2. Cycle 2: Inspect (Q_0=0, Q_-1=1) -> Action: A = A + M
   - A <- A + M = 1100 + 0111 = 0011
   - ASR: A = 0001, Q = 1111, Q_-1 = 0
   - Count = 2

3. Cycle 3: Inspect (Q_0=1, Q_-1=0) -> Action: A = A - M
   - A <- A + (-M) = 0001 + 1001 = 1010
   - ASR: A = 1101, Q = 0111, Q_-1 = 1
   - Count = 1

4. Cycle 4: Inspect (Q_0=1, Q_-1=1) -> Action: Shift Only
   - ASR: A = 1110, Q = 1011, Q_-1 = 1
   - Count = 0 (Stop)

Final Combined Result $(A, Q)$: $11101011_2$
Convert from 2's complement: Flip bits $\rightarrow 00010100_2 + 1 = 00010101_2 = -21$ Correct: $7 \times -3 = -21$

Chapter 5: Memory System & Cache Organization

Memory Hierarchy Pyramid

         /  Registers  \           <- Micro-seconds / Smallest Capacity / Highest Cost
        / Cache (L1/L2) \
       /   Main Memory   \         <- RAM (SRAM / DRAM)
      / Secondary Storage \        <- Hard Drives / SSDs / High Capacity / Lowest Cost

Cache Mapping Techniques

Cache memory bridges the speed gap between CPU registers and main RAM. There are three primary mapping techniques:

  ┌───────────────────┐    ┌───────────────────┐    ┌───────────────────┐
  │  Direct Mapping   │    │Fully Associative  │    │ Set-Associative   │
  ├───────────────────┤    ├───────────────────┤    ├───────────────────┤
  │ Block maps to ONE │    │ Block can go in   │    │ Block maps to ANY │
  │ specific cache    │    │ ANY available     │    │ line inside a     │
  │ line (i mod N).   │    │ cache line.       │    │ assigned set.     │
  └───────────────────┘    └───────────────────┘    └───────────────────┘
  • Direct Mapping:
    • Formula: $\text{Cache Line Number} = (\text{Main Memory Block Number}) \bmod (\text{Total Cache Lines})$
    • Advantage: Extremely fast hardware check.
    • Disadvantage: High conflict misses if two active blocks map to the same line.
  • Fully Associative Mapping:
    • Any block from RAM can sit in any empty cache line.
    • Advantage: Minimum cache misses.
    • Disadvantage: Requires expensive associative search logic circuits.
  • Set-Associative Mapping (Best Compromise):
    • Cache is divided into sets of $k$ lines ($k$-way set associative).
    • Formula: $\text{Cache Set} = (\text{Main Memory Block Number}) \bmod (\text{Total Sets})$

Chapter 6: Input-Output (I/O) & Direct Memory Access (DMA)

Comparing Transfer Modes

Feature Programmed I/O Interrupt-Driven I/O Direct Memory Access (DMA)
CPU Involvement Continuous polling Interrupted only when data ready Zero during block transfer
Transfer Speed Very Slow Moderate Extremely Fast
Best For Simple low-speed chips Keyboards, Mouse Hard Disks, GPUs, Network Cards

DMA Operation Sequence

When bulk data must move between an I/O device and RAM, the CPU hands control over to the DMA Controller:

  1. CPU sends starting memory address, word count, and Read/Write signal to the DMA controller.
  2. CPU requests bus control (Bus Grant signal).
  3. DMA controller transfers the entire block of data directly to/from RAM word by word.
  4. Once completed, DMA raises a single hardware interrupt to notify the CPU that the transfer is done.

Chapter 7: Instruction Pipelining & Hazards

Key Concept: Pipelining overlaps the execution of multiple instructions, running different execution stages simultaneously on separate hardware circuits. 
Clock Cycles ──►  1     2     3     4     5     6
Instruction 1  [ IF ][ ID ][ EX ][ WB ]
Instruction 2        [ IF ][ ID ][ EX ][ WB ]
Instruction 3              [ IF ][ ID ][ EX ][ WB ]

(IF = Instruction Fetch, ID = Instruction Decode, EX = Execute, WB = Write Back)

Speedup Formula

For $n$ instructions executed through a $k$-stage pipeline:

$$S_k = \frac{\text{Time taken without pipeline}}{\text{Time taken with pipeline}} = \frac{n \cdot k}{k + (n - 1)}$$

Pipeline Hazards (Stalls)

Factors that disrupt the pipeline flow and force "bubble" delays:

  • Structural Hazard: Two instructions need the same hardware resource at the same time (e.g., both needing to access memory simultaneously).
  • Data Hazard: An instruction depends on the output of a prior instruction that hasn't completed its Write-Back stage yet.
  • Control Hazard: Caused by branch or jump instructions, where the CPU fetches the wrong sequence of instructions before evaluating the branch condition.
