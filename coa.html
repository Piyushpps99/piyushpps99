Binary Division
Restoring Division Method

Binary division is performed similarly to decimal long division but using binary arithmetic. The restoring division algorithm is a classic method used in hardware for unsigned integer division.

Restoring Division Algorithm Steps

1. Initialize: Load Dividend into Register A (or AQ). Load Divisor into M. Set count = n
2. Shift left the AQ register pair by 1 bit
3. Subtract M from A   (A ← A − M)
4. Check sign of A:
   • If A ≥ 0 (MSB = 0): Set Q0 = 1
   • If A < 0 (MSB = 1): Restore A ← A + M, set Q0 = 0
5. Decrement count. If count ≠ 0 → go to step 2
6. Result: Quotient in Q, Remainder in A

Example 1: Divide 8 by 3 (4-bit)

Dividend = 8 = 10002, Divisor = 3 = 00112
AQ starts with A = 0000, Q = 1000

Step Operation A (Remainder) Q (Quotient) Action / Remark
Init Load 0000 1000 A=0, Q=Dividend, M=0011
1 Shift Left 0001 0000 AQ shifted left
A − M 1110 0000 0001−0011 = −2 (negative)
Restore + Q0=0 0001 0000 A ← A+M; Q0=0
2 Shift Left 0010 0000 AQ shifted left
A − M 1111 0000 0010−0011 = −1 (negative)
Restore + Q0=0 0010 0000 A ← A+M; Q0=0
3 Shift Left 0100 0000 AQ shifted left
A − M 0001 0000 0100−0011 = +1 (positive)
Set Q0=1 0001 0001 No restore; Q0=1
4 Shift Left 0010 0010 AQ shifted left
A − M 1111 0010 0010−0011 = −1 (negative)
Restore + Q0=0 0010 0010 A ← A+M; Q0=0
Final Result: Quotient Q = 00102 = 2, Remainder A = 00102 = 2
Verification: 8 = 3 × 2 + 2 ✓

Example 2: 15 ÷ 3

Dividend = 15 = 000011112, Divisor = 3 = 00112
Result: Quotient = 01012 = 5, Remainder = 0

Note: Non-restoring division is a faster variant that avoids the restore step by conditionally adding or subtracting based on the previous result.

Hardwired Controller Design

A hardwired control unit generates control signals using a fixed logic circuit composed of gates, flip-flops, decoders, and a finite-state machine (FSM). The control logic is permanently wired; changing the instruction set requires redesigning the hardware.

Key Characteristics

⚡ Fast Operation

Combinational + sequential logic with minimal delay

💰 High Cost

Hardware cost & complexity rises with instruction set size

🔒 Hard to Modify

Difficult to change once fabricated

🎯 Best For

RISC processors & simple CPUs where speed is critical

Methods to Design Hardwired Controllers

1. State Table / State Diagram Method

Identify all control states needed for each instruction micro-operation. Draw a state diagram (or state table). Derive Boolean equations for next-state logic and output control signals. Implement with flip-flops and combinational gates.

2. Sequence Counter + Decoder Method

A binary counter generates a sequence of timing signals (T0, T1, T2, …). A decoder expands the counter value into one-hot timing signals. Control signals are formed by ANDing timing signals with instruction decoder outputs (and status flags). Common in simple CPUs with fetch–decode–execute cycles.

3. Delay Element / Timing Signal Generator

A ring counter or chain of delay elements produces successive control pulses. Suitable for very simple controllers with fixed timing.

4. PLA / PAL Based Design

Programmable Logic Arrays implement the complex Boolean functions of next-state and output logic in a compact, structured way while remaining hardwired after programming.

Typical Path: Instruction Register → Opcode Decoder → Control Logic (with timing inputs & condition flags) → Control Signals (to ALU, registers, memory, buses)

ROM and IC Package Pins

A ROM of organization m × n has m addressable locations, each storing an n-bit word.

Example: 1024 × 8 ROM

  • Number of addressable locations = 1024 = 210 → 10 address pins (A0–A9)
  • Data width = 8 bits → 8 data pins (D0–D7)
  • Additional pins typically required:
    • Chip Enable / Chip Select (CE or CS) — 1 pin
    • Output Enable (OE) — 1 pin
    • Power (VCC) and Ground (GND) — 2 pins
Minimum total pins ≈ 10 (addr) + 8 (data) + 1 (CE) + 1 (OE) + 2 (power) = 22 pins
Commercial packages often use 24-pin or 28-pin DIPs for convenience and extra features.
Block Diagram of 1024 × 8 ROM
        +---------------------------------------+
        |              1024 × 8 ROM             |
        |                                       |
        |   A0 ──┐                              |
        |   A1 ──┤                              |
        |   A2 ──┤   Address                    |
        |   ...  ├── Decoder ── 1024 rows       |
        |   A9 ──┘         of 8-bit storage     |
        |                                       |
        |   CE ──── Chip Enable                 |
        |   OE ──── Output Enable               |
        |                                       |
        |              8-bit Data Out           |
        |   D0 D1 D2 D3 D4 D5 D6 D7             |
        +---------------------------------------+
General Formula: For a 2k × n ROM → k address lines, n data lines, plus control and power pins.

Memory Organization
2D and 2½D

Memory chips are organized internally to balance speed, density, and pin count.

2D Organization (Two-Dimensional)

Memory cells are arranged in a rectangular array of rows and columns. An address is split into a row address and a column address. A row decoder selects one entire row; a column decoder (or multiplexer) selects the desired bit/word from that row. Access requires activating both row and column paths. Simple, but decoder size grows linearly with the number of rows/columns, limiting practical size.

2½D Organization (Two-and-a-Half Dimensional)

Also called 2.5D organization. The memory is divided into several smaller 2D arrays (banks or mats). The address is partitioned into: bank select bits + row bits + column bits. Only the selected bank is activated. This reduces the length of word lines and bit lines inside each bank, lowering capacitance and therefore improving access time and reducing power. It also allows interleaved access and higher bandwidth.

How Access Time is Improved

  • Shorter bit-lines and word-lines → smaller RC delay → faster sensing
  • Parallelism: multiple banks can be accessed concurrently or in a pipelined fashion
  • Reduced decoder complexity per bank
  • Modern DRAMs and SRAMs extensively use multi-bank 2½D (and 3D-stacked) organizations to achieve both high density and acceptable latency/bandwidth

DMA Controller

Direct Memory Access (DMA) allows high-speed I/O devices to transfer data directly to/from main memory without continuous CPU intervention, freeing the processor for other work.

Block Diagram of a Typical DMA Controller
        +--------------------------------------------------+
        |                  DMA Controller                  |
        |                                                  |
        |  +-----------+    +--------------------------+   |
        |  | Address   |    |   Word Count Register    |   |
        |  | Register  |    +--------------------------+   |
        |  +-----------+    +--------------------------+   |
        |                   | Control / Status Register|   |
        |  +-----------+    +--------------------------+   |
        |  | Data      |                                   |
        |  | Buffer    |    +--------------------------+   |
        |  +-----------+    | Priority / Arbiter Logic |   |
        |                   +--------------------------+   |
        |                                                  |
        |  Interface to CPU Bus          Interface to I/O  |
        |  (Address, Data, Control)      Device(s)         |
        +--------------------------------------------------+
              ↑ ↓                          ↑ ↓
           System Bus                   I/O Device

Main components: Address Register (holds starting memory address), Word Count Register (number of words still to transfer), Control/Status Register, Data Buffer, and bus request/acknowledge logic.

Why Read and Write Control Lines are Bidirectional

When the CPU is the bus master, it drives the memory Read/Write signals. When the DMA controller becomes bus master (after obtaining bus grant), it must drive the same Read/Write lines to command memory. Therefore the DMA controller’s Read and Write control pins must be able both to receive signals (when CPU is master) and to drive signals (when DMA is master). Hence they are bidirectional (or implemented with tri-state drivers). This allows the DMA controller to take full control of the memory bus during a transfer cycle.

Serial Communication

Serial communication is the process of sending data one bit at a time, sequentially, over a single communication channel or wire. It contrasts with parallel communication, which sends multiple bits simultaneously over multiple wires.

✅ Advantages

Fewer wires, longer distance capability, lower cost, reduced crosstalk

⚠️ Disadvantages

Slower than parallel for short distances (modern high-speed serial links overcome this)

Transmission Modes

Mode Description Example
Simplex Data flows in only one direction Keyboard → Computer, Radio broadcast
Half-Duplex Data can flow both ways, but not simultaneously. Devices take turns Walkie-talkie, older RS-485
Full-Duplex Data flows in both directions simultaneously. Requires separate paths or echo cancellation Telephone, modern Ethernet, RS-232
Serial communication may also be classified as asynchronous (start/stop bits, no shared clock) or synchronous (shared clock or recovered clock, continuous bit stream).

Addressing Modes

Addressing modes define how the CPU calculates the effective address of an operand. They provide flexibility in programming and help reduce instruction size.

Mode Description Example Effective Address
Immediate Operand is part of the instruction itself MOV A, #25H Operand = 25H (no memory access)
Direct / Absolute Instruction contains the full memory address MOV A, 2000H EA = 2000H
Register Operand is in a CPU register ADD B, C Operand in register C
Register Indirect Register contains the address of the operand MOV A, @R0 or MOV A, (BX) EA = content of R0 / BX
Indexed EA = base / index register + displacement MOV A, 1000H(X) or ARRAY[SI] EA = 1000H + X (or ARRAY + SI)
Base + Index EA = base register + index register (+disp) MOV A, [BX+SI] EA = BX + SI
Relative EA = PC + displacement (for branches) JZ LABEL EA = PC + signed offset
Implied / Implicit Operand is implied by the opcode CMA (complement accumulator) Operand = Accumulator
Auto-inc / dec Register used as pointer, then updated MOV A, (R1)+ EA = R1; then R1 ← R1+1
Illustration of Indexed Addressing: Suppose array BASE is at 2000H and index register SI = 05H. Instruction MOV AL, [BASE+SI] fetches the byte at effective address 2005H.

Cache Mapping Techniques

Cache mapping decides where a main-memory block can be placed in the cache.

Direct Mapping – Worked Example

Assume: Main memory = 16 KB, Cache = 1 KB, Block/Line size = 16 bytes. Word size = 1 byte (byte-addressable).

  • Number of main memory blocks = 16 KB / 16 B = 1024 blocks
  • Number of cache lines = 1 KB / 16 B = 64 lines
  • Address length = log2(16 KB) = 14 bits

Address format for Direct Mapping

  • Block offset (word offset) = log2(16) = 4 bits
  • Index (cache line) = log2(64) = 6 bits
  • Tag = 14 − 6 − 4 = 4 bits
Mapping rule: Cache line number = (Main memory block number) mod (Number of cache lines)

General Formulas (Direct Mapping)

Given: Main memory size M, Cache size C, Line size L (all in bytes), byte-addressable.

  • Address bits = log2(M)
  • Offset bits = log2(L)
  • Index bits = log2(C / L)
  • Tag bits = Address bits − Index bits − Offset bits
Fully Associative: no index bits; entire address except offset is tag (any block can go anywhere).
Set-Associative: index selects a set; tag identifies the block within the set.

IEEE-754 Floating-Point Representation

Single-precision (32-bit) format: 1 sign bit + 8 exponent bits (bias 127) + 23 mantissa bits.

Example 1: Convert −19.375 to IEEE-754 Single Precision

// Step 1 – Sign
Negative → Sign bit = 1

// Step 2 – Convert absolute value 19.375 to binary
19 = 100112
0.375 = 0.0112   (0.375 = 1/4 + 1/8)
→ 19.375 = 10011.0112

// Step 3 – Normalize
1.0011011 × 24
Mantissa (fraction) = 0011011 0000000000000000  (23 bits, leading 1 hidden)

// Step 4 – Exponent
True exponent = 4; Biased = 4 + 127 = 131 = 100000112
Final 32-bit pattern:
Sign | Exponent   | Mantissa
1     | 10000011 | 00110110000000000000000

Hex: 0xC19C0000

Example 2: Convert 128.25 to IEEE-754 Single Precision

  • Sign = 0 (positive)
  • 128.25 = 10000000.012 = 1.00000001 × 27
  • Mantissa = 00000001000000000000000
  • Biased exponent = 7 + 127 = 134 = 100001102
Pattern: 0 10000110 00000001000000000000000
Hex: 0x43008000

Virtual Memory and Page Replacement

Virtual Memory is a memory management technique that gives a process the illusion of a large, contiguous address space by using secondary storage (disk) as an extension of main memory. Only the currently needed portions (pages) reside in RAM.

📄 Page Fault

Occurs when the CPU references a page that is not currently present in main memory. The OS must load the page from disk (possibly replacing another page).

📦 Working Set

The set of pages that a process has referenced in the most recent Δ time units. Keeping the working set in memory minimizes page faults.

💥 Thrashing

Severe performance degradation when the system spends most of its time swapping pages rather than executing useful instructions. Caused by too many processes relative to available physical memory.

Page Replacement Algorithms – Simulation

Reference string: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2   (assume 3 frames)

FIFO (First-In-First-Out)

Replace the page that has been in memory the longest.

7F → [7]    0F → [7,0]    1F → [7,0,1]    2F → [2,0,1]    0 → [2,0,1]
3F → [2,3,1]    0F → [2,3,0]    4F → [4,3,0]    2F → [4,2,0]    3F → [4,2,3]
0F → [0,2,3]    3 → [0,2,3]    2 → [0,2,3]
Total page faults = 10

LRU (Least Recently Used)

Replace the page that has not been used for the longest time.

7F → [7]    0F → [7,0]    1F → [7,0,1]    2F → [2,0,1]    0 → [2,0,1]
3F → [2,0,3]    0 → [2,0,3]    4F → [4,0,3]    2F → [4,0,2]    3F → [3,0,2]
0 → [3,0,2]    3 → [3,0,2]    2 → [3,0,2]
Total page faults = 8 (better than FIFO for this string)

Interrupts and Bus Arbitration

Interrupt Hardware

An interrupt is a signal that temporarily suspends the normal execution sequence so the CPU can service an urgent event. Hardware support includes:

  • Interrupt Request (IRQ) lines
  • Interrupt Acknowledge (INTA) line
  • Interrupt vector / priority logic (e.g., daisy chain, priority encoder, APIC)
  • Programmable Interrupt Controller (PIC) or Advanced PIC (APIC) that prioritizes and vectors interrupts

Nested Interrupts

A higher-priority interrupt can interrupt the service routine of a lower-priority interrupt. The CPU (or interrupt controller) saves the current context, raises the priority level, and services the new interrupt. Nesting depth is limited by stack size and priority levels. Proper priority assignment and critical-section protection are essential to avoid priority inversion or unbounded nesting.

Bus Arbitration Methods

Bus arbitration decides which device becomes the bus master when multiple devices request the bus.

Method Description Advantages Disadvantages
Daisy Chaining (Serial) Grant line passed serially through devices; closest to arbiter wins Simple, few wires Fixed priority, slow propagation, fairness issues
Centralized Parallel
(Independent Requests)		 Each device has its own request & grant lines to a central arbiter Fast, flexible priority, fair algorithms possible More wires, complex arbiter
Distributed
(Self-Selection / Collision Detection)		 Devices share request lines and resolve priority among themselves No central bottleneck, scalable More complex logic in each device
Polling Central controller polls devices in turn Simple control, fair Latency depends on poll rate, overhead

Asynchronous Data Transfer Mechanisms

Asynchronous transfers do not use a common clock. Coordination is achieved by handshaking signals (e.g., Request/Acknowledge or Strobe/Acknowledge).

Source-initiated (Strobe)

Source places data and asserts Strobe; destination captures data on Strobe edge. Simple but destination has no way to delay the source.

Handshaking (two-wire)

Source asserts Request (data valid); destination asserts Acknowledge when ready/received; source de-asserts Request; destination de-asserts Ack. This four-phase handshake guarantees reliable transfer regardless of speed differences between source and destination.
