GIT VS. GITHUB

Git and GitHub are fundamental tools in modern software development, but they serve two completely different purposes[cite: 1]. While Git handles local version control on your machine, GitHub acts as a cloud-based platform for remote hosting and team collaboration[cite: 1].

WHAT IS GIT?

Git is a free, open-source, distributed version control system designed to run locally on your computer[cite: 1]. It tracks changes in your source code over time, enabling you to revert to previous file states, manage project history, and isolate experimental features[cite: 1].

  • Core Purpose: Tracks file modifications, manages version history, and maintains local snapshots of your project[cite: 1].
  • Distributed Architecture: Every developer has a complete copy (clone) of the entire project repository and its history directly on their local machine[cite: 1].
  • Key Mechanisms:
    • Staging Area: A pre-commit area (git add) where you prepare specific file changes before permanently snapshotting them[cite: 1].
    • Commits: Permanent snapshots of your staged modifications (git commit) paired with descriptive messages[cite: 1].
    • Branching & Merging: Isolated lines of development (git branch) that allow you to work on separate features without affecting the main codebase, later merging (git merge) them back together[cite: 1].
    • Stashing: Temporarily storing uncommitted work (git stash) to switch contexts quickly without committing incomplete progress[cite: 1].

WHAT IS GITHUB?

GitHub is a cloud-based hosting platform built specifically around Git[cite: 1]. It takes Git's local tracking features and expands them into a centralized ecosystem for team collaboration, code sharing, and project management[cite: 1].

  • Core Purpose: Host remote Git repositories online, enabling teams to review code, synchronize progress, and store off-site backups[cite: 1].
  • Key Features:
    • Remote Repositories: Centralized online repositories (git push and git pull) where team members share local commits[cite: 1].
    • Pull Requests (PRs): A mechanism for developers to propose changes, discuss code, run tests, and request peer reviews before merging into the primary branch[cite: 1].
    • Collaboration Tools: Integrated issue tracking, project boards, wiki documentation, and access controls for team permissions[cite: 1].
    • Ecosystem Services: Native tools for Continuous Integration and Continuous Deployment (CI/CD) via GitHub Actions, as well as educational programs like GitHub Education[cite: 1].

HOW THEY WORK TOGETHER

  • 1. Local Tracking You initialize (git init) or clone (git clone) a project on your computer using Git[cite: 1].
  • 2. Snapshotting You modify code, stage the changes (git add), and commit them locally (git commit)[cite: 1].
  • 3. Synchronizing You connect your local Git repository to a GitHub remote URL (git remote add) and transmit your commits (git push) to the cloud[cite: 1].
  • 4. Collaborating Team members retrieve your updates (git fetch / git pull), review the code via Pull Requests on GitHub, and integrate the changes back into the main project[cite: 1].

INSTALLATION & GUIS

With platform specific installers for Git, GitHub also provides the ease of staying up-to-date with the latest releases of the command line tool while providing a graphical user interface for day-to-day interaction, review, and repository synchronization[cite: 1].

  • GitHub for Windows: https://windows.github.com[cite: 1]
  • GitHub for Mac: https://mac.github.com[cite: 1]
  • Git for All Platforms: http://git-scm.com (For Linux and Solaris platforms, the latest release is available on the official Git web site)[cite: 1]

SETUP

Configuring user information used across all local repositories[cite: 1]
  • git config --global user.name “[firstname lastname]” Set a name that is identifiable for credit when review version history[cite: 1]
  • git config --global user.email “[valid-email]” Set an email address that will be associated with each history marker[cite: 1]
  • git config --global color.ui auto Set automatic command line coloring for Git for easy reviewing[cite: 1]

SETUP & INIT

Configuring user information, initializing and cloning repositories[cite: 1]
  • git init Initialize an existing directory as a Git repository[cite: 1]
  • git clone [url] Retrieve an entire repository from a hosted location via URL[cite: 1]

STAGE & SNAPSHOT

Working with snapshots and the Git staging area[cite: 1]
  • git status Show modified files in working directory, staged for your next commit[cite: 1]
  • git add [file] Add a file as it looks now to your next commit (stage)[cite: 1]
  • git reset [file] Unstage a file while retaining the changes in working directory[cite: 1]
  • git diff Diff of what is changed but not staged[cite: 1]
  • git diff --staged Diff of what is staged but not yet committed[cite: 1]
  • git commit -m “[descriptive message]” Commit your staged content as a new commit snapshot[cite: 1]

BRANCH & MERGE

Isolating work in branches, changing context, and integrating changes[cite: 1]
  • git branch List your branches. A * will appear next to the currently active branch[cite: 1]
  • git branch [branch-name] Create a new branch at the current commit[cite: 1]
  • git checkout Switch to another branch and check it out into your working directory[cite: 1]
  • git merge [branch] Merge the specified branch’s history into the current one[cite: 1]
  • git log Show all commits in the current branch’s history[cite: 1]

SHARE & UPDATE

Retrieving updates from another repository and updating local repos[cite: 1]
  • git remote add [alias] [url] Add a git URL as an alias[cite: 1]
  • git fetch [alias] Fetch down all the branches from that Git remote[cite: 1]
  • git merge [alias]/[branch] Merge a remote branch into your current branch to bring it up to date[cite: 1]
  • git push [alias] [branch] Transmit local branch commits to the remote repository branch[cite: 1]
  • git pull Fetch and merge any commits from the tracking remote branch[cite: 1]

TRACKING PATH CHANGES

Versioning file removes and path changes[cite: 1]
  • git rm [file] Delete the file from project and stage the removal for commit[cite: 1]
  • git mv [existing-path] [new-path] Change an existing file path and stage the move[cite: 1]
  • git log --stat -M Show all commit logs with indication of any paths that moved[cite: 1]

TEMPORARY COMMITS

Temporarily store modified, tracked files in order to change branches[cite: 1]
  • git stash Save modified and staged changes[cite: 1]
  • git stash list List stack-order of stashed file changes[cite: 1]
  • git stash pop Write working from top of stash stack[cite: 1]
  • git stash drop Discard the changes from top of stash stack[cite: 1]

REWRITE HISTORY

Rewriting branches, updating commits and clearing history[cite: 1]
  • git rebase [branch] Apply any commits of current branch ahead of specified one[cite: 1]
  • git reset --hard [commit] Clear staging area, rewrite working tree from specified commit[cite: 1]

INSPECT & COMPARE

Examining logs, diffs and object information[cite: 1]
  • git log Show the commit history for the currently active branch[cite: 1]
  • git log branchB..branchA Show the commits on branchA that are not on branchB[cite: 1]
  • git log --follow [file] Show the commits that changed file, even across renames[cite: 1]
  • git diff branchB...branchA Show the diff of what is in branchA that is not in branchB[cite: 1]
  • git show [SHA] Show any object in Git in human-readable format[cite: 1]

IGNORING PATTERNS

Preventing unintentional staging or commiting of files[cite: 1]
  • git config --global core.excludesfile [file] System wide ignore pattern for all local repositories[cite: 1]

Save a file with desired patterns as .gitignore with either direct string matches or wildcard globs (e.g., logs/, *.notes, pattern*/)[cite: 1].
